## What this is

LLM Tuna — a web platform for fine-tuning open-source LLMs (Llama 3.1 8B via LoRA) and comparing base vs fine-tuned outputs. Two-app monorepo:

- **backend/** — FastAPI + SQLAlchemy 2 + Pydantic v2 REST API, PostgreSQL storage, Hugging Face transformers/peft for training, evaluation, and inference.
- **frontend/** — Next.js 14 (App Router) + React 18 + TypeScript + Tailwind + axios + recharts. Talks to the backend at `NEXT_PUBLIC_API_URL` (default `http://localhost:8000`).

## Commands

The repo has **no committed `docker-compose.yml`** (it is gitignored) and no Makefile — local dev runs the two apps plus Postgres directly.

### Start (full dev stack)

```bash
# 1. Postgres (service or Docker). Credentials the backend expects by default:
#    postgresql://finetune:finetune@localhost:5432/finetune_db
sudo service postgresql start
sudo -u postgres psql -c "CREATE USER finetune WITH PASSWORD 'finetune' CREATEDB;"   # skip if exists
sudo -u postgres createdb -O finetune finetune_db
# 2. Backend (uv-managed 3.11 venv; torch needs --index-url .../whl/cpu in a CPU sandbox)
cd backend && uv venv --python 3.11 .venv
uv pip install --python .venv/bin/python torch==2.1.1 --index-url https://download.pytorch.org/whl/cpu
uv pip install --python .venv/bin/python -r requirements.txt 'numpy<2'   # numpy>=2 breaks torch 2.1.1
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
# 3. Frontend
cd frontend && npm install && NEXT_PUBLIC_API_URL=http://localhost:8000 npm run dev
```

- Backend: http://localhost:8000 — health `GET /health`, docs `/docs`
- Frontend: http://localhost:3000
- DB tables (`datasets`, `training_jobs`, `evaluations`, `user_ratings`) are auto-created by `init_db()` via `create_all()` on backend startup — no migration step.

If `docker-compose.yml` exists locally (untracked), `docker-compose up -d` starts all three services (Postgres 5432, backend 8000, frontend 3000).

## Codebase map

Two top-level dirs; full table in [`codebase-map.md`](codebase-map.md). Key paths:

- `backend/app/main.py` — FastAPI app, CORS (allows localhost:3000), startup `init_db()`
- `backend/app/routers/` — `datasets`, `training`, `evaluation`, `inference` endpoints
- `backend/app/ml/` — `data_validator` (tiktoken), `trainer` (LoRA), `evaluator`, `inference` (torch/transformers/peft)
- `backend/app/database.py` — engine/session from `DATABASE_URL`; `backend/app/models.py` — SQLAlchemy models
- `frontend/app/` — pages: dashboard `/`, `datasets/`, `training/[id]/`, `evaluation/[id]/`; `app/api/training/route.ts` is a Next route handler
- `frontend/lib/api.ts` — axios client → `NEXT_PUBLIC_API_URL`

## Gotchas

- System Python is 3.13; `requirements.txt` pins torch 2.1.1 → must use Python 3.11 venv (uv provides it).
- Pin `numpy<2` — torch 2.1.1 is incompatible with numpy 2.x (silent failures in the ML path).
- `docker-compose.yml` is gitignored by design; don't commit one without asking.
- Sandbox persistence: Postgres was started via `service`; in a fresh snapshot-restore shell, re-run `sudo service postgresql start` if connections fail.
